# Windows DOSZ Assembly Guide

ExoWin Pocket launches most games by asking DOSBox Pure to mount a shared Windows 3.1 environment and then applying a per-game save overlay. That shared environment is a ZIP-format archive named `Windows311-EXOWIN.dosz`.

The repository and APK do not include Windows, drivers, license keys, installer media, or `RUNEXIT.EXE`. Build the archive only from software you are licensed to use.

## Tested Target

The MVP was developed against this general configuration:

- Windows 3.1 or Windows for Workgroups 3.11 installed in `C:\WINDOWS`.
- 640x480, 256-color S3-compatible display driver. The tested shell reports `display.drv=s3vsnv.drv` in `SYSTEM.INI`.
- Sound Blaster 16 using base address 220, IRQ 7, DMA 1, high DMA 5, and MIDI port 330.
- VBMouse absolute-pointer driver installed as `C:\WINDOWS\SYSTEM\VBMOUSE.DRV`.
- A compatible 16-bit `C:\RUNEXIT\RUNEXIT.EXE` helper.

Other configurations may work, but this is the known-good starting point. Configure and test Windows in DOSBox Pure before packaging it.

## 1. Create a Clean Working Directory

Create an empty directory on a computer, for example:

```text
C:\dosz-build\Windows311-EXOWIN\
```

This directory will become the root of the archive. Do not put another wrapper directory inside it.

## 2. Install Windows

Using legally obtained installation media and a valid license, install Windows 3.1 or Windows for Workgroups 3.11 to `C:\WINDOWS` in a DOSBox environment.

Configure the virtual machine to match DOSBox Pure as closely as practical:

- VGA/SVGA display with an S3-compatible 256-color driver.
- Sound Blaster 16 at address 220, IRQ 7, DMA 1, high DMA 5.
- MIDI at port 330 if MIDI playback is wanted.
- At least 16 MB of memory while testing; individual games may need a different DOSBox Pure memory setting.

Start Windows, verify Program Manager appears, verify the mouse works, play a Windows sound, and exit cleanly before continuing.

## 3. Install Absolute Mouse Support

Install a Windows 3.x-compatible VBMouse driver. Confirm that the working Windows tree contains:

```text
WINDOWS\SYSTEM\VBMOUSE.DRV
```

The relevant `WINDOWS\SYSTEM.INI` entries should be equivalent to:

```ini
[boot]
mouse.drv=vbmouse.drv

[386Enh]
mouse=*vmd
```

ExoWin Pocket reads mouse settings and driver files from the generic shell and copies them into games that supply their own Windows directory. Missing or mismatched mouse support can therefore affect both ordinary games and titles with custom Windows trees.

## 4. Add the Exit Helper

Create this directory in the archive root:

```text
RUNEXIT\
```

Place a legally obtained or independently built 16-bit Windows 3.x helper at:

```text
RUNEXIT\RUNEXIT.EXE
```

The helper is not part of Windows and is not supplied by this project. It must accept the launch form generated by ExoWin Pocket:

```text
C:\WINDOWS\WIN.COM C:\RUNEXIT\RUNEXIT.EXE /delay=1 /pwd=C:\GAME C:\GAME\GAME.EXE [arguments]
```

It must start the requested Windows program in the requested working directory, wait for that program to finish, and then let Windows close so control returns to DOSBox Pure. A different helper with the same filename but different argument handling can produce `Error 2`, `Error 21`, an immediate return to RetroArch, or a Windows session that never exits.

Test this exact argument style manually with a simple Windows program before packaging the shell.

## 5. Add the Root Startup Batch File

Create `WINDOWS.BAT` at the archive root with CRLF line endings:

```bat
@echo off
path=C:\;Z:\;C:\WINDOWS\
set TEMP=C:\TEMP
C:\WINDOWS\WIN.COM
```

Also create an empty `TEMP` directory. Do not make `WINDOWS.BAT` launch a particular game; ExoWin Pocket replaces it in each game's DOSBox Pure overlay.

## 6. Check the Required Layout

At minimum, the working directory should look like this:

```text
Windows311-EXOWIN\
|-- WINDOWS.BAT
|-- RUNEXIT\
|   `-- RUNEXIT.EXE
|-- TEMP\
`-- WINDOWS\
    |-- WIN.COM
    |-- WIN.INI
    |-- SYSTEM.INI
    `-- SYSTEM\
        `-- VBMOUSE.DRV
```

Keep all Windows system files and installed drivers beneath `WINDOWS`. Driver installation source directories such as `s3`, `SB16`, or `vbados` may also remain at the archive root if your Windows setup depends on them, but installer media and personal files are not required at runtime.

The most common packaging mistake is an extra directory level. This is wrong:

```text
Windows311-EXOWIN.dosz -> Windows311-EXOWIN\WINDOWS\WIN.COM
```

This is correct:

```text
Windows311-EXOWIN.dosz -> WINDOWS\WIN.COM
```

## 7. Package the Archive

With 7-Zip installed, run this from inside the working directory:

```powershell
Set-Location C:\dosz-build\Windows311-EXOWIN
7z a -tzip ..\Windows311-EXOWIN.dosz .\WINDOWS.BAT .\WINDOWS .\RUNEXIT .\TEMP
```

If your tested shell intentionally retains driver source directories, add them to the same command:

```powershell
7z a -tzip ..\Windows311-EXOWIN.dosz .\WINDOWS.BAT .\WINDOWS .\RUNEXIT .\TEMP .\s3 .\SB16 .\vbados
```

The `.dosz` extension is intentional, but the archive format is ordinary ZIP. Do not create a 7z-format archive and merely rename it.

Inspect the result:

```powershell
7z l ..\Windows311-EXOWIN.dosz
```

Confirm that `WINDOWS.BAT`, `WINDOWS/WIN.COM`, `WINDOWS/SYSTEM.INI`, `WINDOWS/SYSTEM/VBMOUSE.DRV`, and `RUNEXIT/RUNEXIT.EXE` appear directly beneath the archive root.

## 8. Install It on Android

Copy the archive to RetroArch's system directory:

```powershell
adb push ..\Windows311-EXOWIN.dosz /storage/emulated/0/RetroArch/system/
adb shell ls -l /storage/emulated/0/RetroArch/system/Windows311-EXOWIN.dosz
```

You can use an Android file manager instead. The final default path must be:

```text
/storage/emulated/0/RetroArch/system/Windows311-EXOWIN.dosz
```

If RetroArch uses a different system directory, either make its directory match this path or update ExoWin Pocket's stored `android_retroarch_system_dir` configuration in a custom build.

## 9. Validate Before Using ExoWin Pocket

In RetroArch, confirm that DOSBox Pure is installed and that the system and save directories are writable. Load the DOSZ directly if your DOSBox Pure version offers it, or otherwise test the same unpacked Windows tree in DOSBox Pure. Windows should open, the pointer should track correctly, sound should work, and exiting Windows should return to RetroArch.

Then launch a small installed game from ExoWin Pocket. The app should create either `<game>.pure.zip` or `<game>.save.zip` under:

```text
/storage/emulated/0/RetroArch/saves/DOSBox-pure
```

That overlay contains generated files such as `AUTOBOOT.DBP` and `WINDOWS.BAT`; it is not another copy of Windows. ExoWin Pocket may choose `.save.zip` for games that need their single top-level directory treated as drive C. Do not keep both extensions for the same game unless diagnosing a problem.

## Troubleshooting

- **"The ExoWin Windows shell is missing"**: check the exact filename, extension, and RetroArch system directory.
- **Windows opens and immediately exits**: validate `WINDOWS.BAT`, the generated game overlay, and the `RUNEXIT.EXE` argument contract.
- **`Error 2`**: Windows could not find a requested file or the helper interpreted its arguments differently. Check `RUNEXIT.EXE`, `/pwd`, game paths, and the archive root layout.
- **`Error 21`**: treat this first as a helper/configuration compatibility problem. Re-test with the known argument form and DOSBox Pure CPU/memory/cycle settings.
- **Mouse does not work in a custom Windows game**: verify `VBMOUSE.DRV` and both `SYSTEM.INI` entries in the generic shell.
- **Game opens but behaves badly**: change DOSBox Pure's per-game core options. The correct memory, CPU type, core mode, and cycles vary by title.
- **A re-test still uses old behavior**: move aside that game's existing `.pure.zip` or `.save.zip` overlay and launch again so ExoWin Pocket can regenerate it. Preserve the old file if it may contain saves.
